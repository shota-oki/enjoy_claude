## 1. 概要
開発に使う環境、ソースコードの置き場所、ブランチの使い方、コーディング規約、開発中に iPhone 実機で確認する方法を定める。

## 2. 開発環境

| 項目 | 内容 |
|------|------|
| OS | Windows 11 |
| エディタ | VS Code（拡張機能：ESLint、Prettier、Claude Code） |
| Node.js | 22系（LTS）。バージョンは `.nvmrc` と `package.json` の `engines` に記載して固定する |
| パッケージ管理 | npm。`package-lock.json` をリポジトリに含め、全員・CIで同じバージョンを使う |
| ブラウザ（PC） | Microsoft Edge または Google Chrome（開発時の動作確認・デバッグ） |
| 実機 | 利用者の iPhone（iOS Safari）。対応バージョンは要件定義書 6章のとおり |

## 3. ソースコードの置き場所

```
enjoy_claude/                 … 現在のリポジトリ
├── docs/                     … 設計書（既存）
├── app/                      … アプリのソースコード一式（新規）
│   ├── src/                  … 処理設計書 共通 5章のディレクトリ構成
│   ├── public/               … アイコン等、そのまま配信するファイル
│   ├── tests/                … 結合テスト・テスト用データ
│   ├── package.json
│   ├── vite.config.ts
│   └── tsconfig.json
├── .github/workflows/        … GitHub Actions の定義（M-03）
├── CLAUDE.md
└── README.md
```

- アプリのコードは `app/` にまとめ、設計書（`docs/`）と分ける
- 単体テストのファイルは、対象のファイルと同じ場所に `〇〇.test.ts` として置く

## 4. 開発で使うコマンド（`app/` で実行）

| コマンド | 内容 |
|---------|------|
| `npm run dev` | 開発サーバーを起動する（PCのブラウザで確認） |
| `npm run dev:lan` | 同じWi-Fiの iPhone から HTTPS で接続できる開発サーバーを起動する（5章） |
| `npm run build` | 本番用にビルドする |
| `npm run preview:lan` | ビルド結果を iPhone から HTTPS で確認する（PWA・オフラインの確認用。5章） |
| `npm run test` | 単体テスト・結合テストを実行する |
| `npm run lint` | ESLint で規約チェックを行う |
| `npm run typecheck` | TypeScript の型チェックを行う |
| `npm run format` | Prettier で整形する |
| `npm run seed:sample` | 確認用の大量データ（300件）を作る（テスト方針書） |

## 5. iPhone 実機での確認方法
Service Worker（オフライン動作・更新）は HTTPS でしか動かないため、PCの開発サーバーを HTTPS で公開して iPhone から接続する。

| 確認内容 | 方法 |
|---------|------|
| 画面の見た目・操作・カメラ | `npm run dev:lan` で起動し、iPhone の Safari で PC の IPアドレス（`https://192.168.x.x:5173` 等）を開く |
| PWA（ホーム画面追加・オフライン・更新） | `npm run build` 後に `npm run preview:lan` で起動し、iPhone の Safari で開いてホーム画面に追加する |

- HTTPS 化には開発用の自己署名証明書（Vite の basic-ssl プラグイン）を使う。初回接続時に Safari で警告が出るため、内容を確認して接続を許可する
- PC と iPhone は同じ Wi-Fi に接続する。Windows のファイアウォールで、開発サーバーの通信（Node.js）を「プライベートネットワーク」に限って許可する
- **注意：本番の公開URLで開発中の確認をしない。** 本番URLで開いたアプリのデータ（IndexedDB）は、普段使いの本番データと同じ領域になる。確認用のデータが本番データに混ざらないよう、確認は必ず PC の開発サーバー（別のURL）で行う

## 6. ブランチ・コミットの運用

| 項目 | 内容 |
|------|------|
| main ブランチ | 常に動作する状態を保つ。公開（M-03）は main から行う |
| 作業ブランチ | 機能・修正ごとに `feature/〇〇`、`fix/〇〇` を作り、完成したら main に取り込む |
| コミットメッセージ | 日本語で、変更内容がわかる1行の要約を書く（例：「アイテム一覧の絞り込みを実装」） |
| 取り込み前の確認 | `lint`・`typecheck`・`test` がすべて通ること |

## 7. コーディング規約

| 項目 | 規約 |
|------|------|
| 整形 | Prettier の標準設定に従う（自動整形） |
| 静的解析 | ESLint（TypeScript 用の推奨設定＋React Hooks の規則）でエラー0件とする |
| 型 | `any` は使わない。DBのデータ・フォームの値などは `types/models.ts` に型を定義する |
| 名前 | コンポーネントとそのファイルは PascalCase（例：`ItemListScreen.tsx`）、関数・変数は camelCase、定数は UPPER_SNAKE_CASE |
| 文言 | 画面に表示するメッセージは `constants/messages.ts` に定義し、コード中に直接書かない（画面詳細設計書 共通仕様 7章のIDで参照） |
| 固定値 | 上限値・カテゴリ等の固定値は `constants/` に定義し、コード中に数値・文字列を直接書かない |
| コメント | 日本語で書く。「何をしているか」よりも「なぜそうしているか」を書く |
| 依存関係 | 処理設計書 共通 4章の層構成に従い、下の層から上の層を呼び出さない |
