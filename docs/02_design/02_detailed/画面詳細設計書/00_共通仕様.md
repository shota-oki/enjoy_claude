## 1. 本書の方針
- 画面詳細設計書は画面単位でファイルを分けて作成する。本書は全画面に共通する仕様を定める
- 画面定義書で合意した画面構成・遷移を前提に、各画面の項目の表示内容・表示形式・初期値、状態ごとの表示、操作時の処理、入力チェック、メッセージを定める
- 寸法（余白・文字サイズ・部品の大きさ等）は定めない。モックの見た目を参考とし、実装時に調整する
- データ項目は要件定義書 5.2「アイテムの管理項目」の項目名で記載する。物理的な項目名はDB設計で定める
- 各画面で新たに定めた仕様のうち確認が必要なものは、各ファイルの「確認事項」に記載する

## 3. 表示形式

| 対象 | 表示形式 | 例 |
|------|---------|----|
| 日付 | YYYY/MM/DD | 2026/05/10 |
| 金額 | 「¥」＋3桁区切り | ¥12,100 |
| 件数 | 数値＋「点」 | 16点 |
| 未入力の任意項目（詳細表示時） | 「未入力」を薄い文字色で表示 | 未入力 |
| 1行に収まらない文字列（一覧・チップ等） | 末尾を「…」で省略 | ネイビーのオックス… |
| 季節 | 春→夏→秋→冬の順で表示（選択した順ではない） | 春 秋 |

## 4. 共通部品

| 部品 | 仕様 |
|------|------|
| ナビゲーションバー | 画面上部に表示。左に「戻る」または「キャンセル」、中央に画面タイトル、右に画面固有の操作ボタン |
| タブバー | SC-05以外の画面の下部に表示。「クローゼット」「設定」の2タブ。表示中のタブをアクセントカラーで表示。タブをタップすると、そのタブの先頭画面（SC-01／SC-06）へ移動する |
| トースト | 画面下部に表示し、約2秒で自動的に消える。操作は不要。表示中に次のトーストが発生した場合は置き換える |
| 確認ダイアログ | iOS標準の確認ダイアログの形式。危険な操作（削除・破棄）のボタンは赤字で表示 |
| 処理中表示 | 写真の読み込み・保存処理中は、対象部分に処理中の表示（スピナー）を出し、二重操作を防ぐため該当ボタンを押せない状態にする |
| 更新の案内 | 新しい版を検知したとき、タブバーの上に MSG-I06「新しいバージョンがあります」と「更新」ボタン・×ボタンを表示する。「更新」で新しい版に切り替えて再読み込みし、SC-01 を表示する。×で閉じた場合は次の確認タイミングで再表示する。SC-05 の表示中は表示せず、SC-05 を閉じたあとに表示する（方式設計書 M-01 4章） |

## 5. 入力の共通ルール
- テキスト入力の前後の空白（全角・半角）は保存時に取り除く。取り除いた結果が空の場合は未入力として扱う
- 入力チェックは「保存」タップ時に行う。エラーのある項目は、修正（入力・選択）した時点でエラー表示を消す
- 入力文字数の上限を超える入力はできないようにする（入力欄で制限する）

## 6. 共通エラー処理

| 発生箇所 | 状況 | 対応 |
|---------|------|------|
| 画面表示時 | 端末内データの読み込みに失敗 | MSG-E12 をダイアログで表示する |
| 保存・削除時 | 端末内データへの書き込みに失敗（容量不足等） | MSG-E11 をダイアログで表示し、入力内容は保持したまま画面に留まる |
