## 1. 概要

| 項目 | 内容 |
|------|------|
| テーブル名 | thumbnails |
| 論理名 | 一覧用画像 |
| 役割 | 写真ごとの小さい画像を保存する。一覧（SC-01）と編集フォームのサムネイル（SC-05）で使う |
| 想定件数 | photos と同数 |
| 関連テーブル | photos（1対1） |

## 2. テーブル定義

| カラム名 | 型 | NULL許可 | 主キー | 外部キー | 説明 |
|---------|----|---------|--------|---------|------|
| photoId | string | - | ○ | photos.id | 元の写真のID（photos と1対1） |
| image | Blob | - | - | - | 画像データ。短辺400pxになるよう縮小し、中央を正方形に切り抜いたJPEG |
| byteSize | number | - | - | - | image のサイズ（バイト） |

## 3. インデックス

| インデックス名 | 対象カラム | 種別 | 用途 |
|----------------|-----------|------|------|
| （主キー） | photoId | UNIQUE | 写真IDによる取得（一覧表示でまとめて取得） |

## 4. 関連する操作

| 操作（共通 6章） | 内容 |
|-----------------|------|
| No.1 アイテム登録 | 写真ごとに追加 |
| No.2 アイテム更新 | 追加された写真の分を追加、取り除かれた写真の分を削除 |
| No.3 アイテム削除 | 対象アイテムの写真の分を削除 |
| No.9 保存容量の取得 | byteSize を合計 |

## 5. 備考
- photos と別テーブルにするのは、一覧表示で元の大きさの画像を読み込まないようにするため（IndexedDB は1件単位で読み込むため、同じレコードに入れると両方読まれる）
