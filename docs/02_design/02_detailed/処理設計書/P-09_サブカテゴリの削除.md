## 1. 概要
アイテムが登録されていないサブカテゴリを削除する。アイテムが登録されている場合は削除しない。SC-08 のアイテム件数の表示もこの処理で取得する。

| 項目 | 内容 |
|------|------|
| 契機 | SC-08 の表示（件数の取得）、削除ボタンのタップ、DL-06 で「削除」をタップ |
| 関連画面 | SC-08（DL-06）、SC-01（選択中のサブカテゴリの解除） |
| 関連テーブル | subcategories（削除）、items（件数の読込） |

## 2. 関数

| 関数名 | 概要 | 入力 | 出力 |
|--------|------|------|------|
| itemRepository.countBySubcategory | サブカテゴリごとのアイテム件数を数える（subcategoryId インデックスを使う） | categoryId | Map（subcategoryId → 件数） |
| subcategoryRepository.remove | アイテムが0件であることを確認して削除する | subcategoryId | なし（1件以上なら InUseError） |

## 3. 処理フロー
1. SC-08 の表示時に `itemRepository.countBySubcategory` で件数を取得し、各行に表示する（DBの変更は自動で反映）
2. 削除ボタンをタップした時点の件数で DL-06 の内容を決める
   - 1件以上：削除不可通知（MSG-C11・C12）を表示して終了する
   - 0件：削除確認（MSG-C10）を表示する
3. 「削除」をタップしたら、処理中状態にして `subcategoryRepository.remove` を呼ぶ。トランザクション内で以下を行う
   1. items の subcategoryId インデックスで、該当アイテムの件数を数える
   2. 1件以上なら InUseError とし、削除しない
   3. 0件なら subcategories から削除する
4. 成功した場合：ダイアログを閉じ、MSG-I03 を表示する。ListStateContext でこのサブカテゴリを選択中であれば「すべて」に戻す
5. InUseError の場合：削除不可通知（MSG-C11・C12）に切り替えて表示する

- 手順3で改めて件数を確認するのは、確認ダイアログを表示してから削除するまでの間に状態が変わる場合に備えるため

## 4. 例外処理

| 状況 | 対応 |
|------|------|
| InUseError | 削除不可通知を表示する |
| 書き込みに失敗 | MSG-E11 を表示する（ERROR ログ） |
| 対象のサブカテゴリがすでに存在しない | 削除済みとみなして成功と同じ扱いにする |
