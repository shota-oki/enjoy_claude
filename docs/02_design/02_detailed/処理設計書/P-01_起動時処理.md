## 1. 概要
アプリを開いたときに1回だけ行う処理。DBの準備、初期サブカテゴリの投入、保存済みの並び順の読み込み、永続保存の要求、起動方法（ホーム画面から／Safariから）の判定を行い、SC-01を表示する。

| 項目 | 内容 |
|------|------|
| 契機 | アプリの起動（`main.tsx` から呼び出す） |
| 関連画面 | SC-01（案内バナーの表示有無） |
| 関連テーブル | subcategories（書込）、settings（読込・書込） |

## 2. 関数

| 関数名 | 概要 | 入力 | 出力 |
|--------|------|------|------|
| appInitializer.initialize | 起動時処理全体を行う | なし | 初期状態（並び順コード、案内バナーを表示するか） |
| seed（db/seed.ts） | 初期サブカテゴリを投入する | なし | なし |
| settingsRepository.get | 設定値を取得する | key | value または undefined |
| settingsRepository.set | 設定値を保存する | key、value | なし |
| storageService.requestPersist | iPhoneに永続保存を要求する（`navigator.storage.persist()`） | なし | boolean（許可されたか） |
| storageService.isStandalone | ホーム画面から起動しているか判定する（`navigator.standalone`、または表示モードが standalone） | なし | boolean |

## 3. 処理フロー
1. DBを開く。開けない場合は MSG-E12 を表示して処理を終える
2. settings の `subcategoriesSeeded` を確認する
   - 未登録の場合：初期サブカテゴリ（DB設計書 T-04 5章）を、カテゴリごとに sortOrder を 10, 20, 30… と採番して登録し、`subcategoriesSeeded` に true を保存する。この2つは1トランザクションで行う
   - 登録済みの場合：何もしない
3. settings の `itemSortOrder` を読み込み、一覧の並び順の初期値とする。未登録、または定義にない値の場合は `created_desc` とする
4. `storageService.requestPersist` で永続保存を要求する。許可されなかった場合や、この機能に対応していない場合も処理を続ける（WARN ログを出力）
5. `storageService.isStandalone` で起動方法を判定し、Safariから開いている場合は案内バナーを表示する状態にする
6. 得た初期状態を ListStateContext に設定し、SC-01 を表示する

## 4. 例外処理

| 状況 | 対応 |
|------|------|
| DBを開けない（手順1） | MSG-E12 を表示する |
| 初期サブカテゴリの投入に失敗（手順2） | トランザクションが取り消されるため `subcategoriesSeeded` は保存されず、次回起動時に再度投入を試みる。今回は MSG-E12 を表示する |
| 並び順の読み込みに失敗（手順3） | `created_desc` として続行する（WARN ログ） |
