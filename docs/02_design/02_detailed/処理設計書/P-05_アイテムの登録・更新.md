## 1. 概要
登録・編集フォームの入力内容をチェックし、アイテムと写真をDBに保存する。登録と更新で共通の処理とし、違いは手順内に記載する。編集フォームを開くときの読み込みもこの処理に含める。

| 項目 | 内容 |
|------|------|
| 契機 | SC-05 の表示（編集時の読み込み）、SC-05 の「保存」 |
| 関連画面 | SC-05、保存後の SC-01／SC-04 |
| 関連テーブル | items、photos、thumbnails（読込・書込） |

## 2. 関数

| 関数名 | 概要 | 入力 | 出力 |
|--------|------|------|------|
| itemRepository.get | アイテムを1件取得する | itemId | Item または undefined |
| photoRepository.getImage | 写真の画像を取得する（編集フォームのサムネイル表示用には一覧用画像を使う） | photoId | Blob |
| itemValidator.validate | 入力チェック（SC-05 5章） | フォームの値、今日の日付 | 項目ごとのエラー（メッセージID）の一覧 |
| itemValidator.toItemInput | フォームの値を保存用の値に変換する | フォームの値 | ItemInput |
| itemRepository.create | アイテムと写真を1トランザクションで登録する | ItemInput、NewPhoto[] | 登録した Item |
| itemRepository.update | アイテムと写真を1トランザクションで更新する | itemId、ItemInput、写真の並び（既存の写真ID または NewPhoto） | 更新した Item |

## 3. 処理フロー

### 3.1 フォームを開く
1. 登録時：画面詳細設計書 SC-05 3章の初期値（一覧で選択中のカテゴリ・サブカテゴリを含む）でフォームを作る
2. 編集時：`itemRepository.get` でアイテムを取得してフォームに設定する。写真は photoIds の順に一覧用画像を取得してサムネイルに表示する。アイテムが存在しない場合は MSG-E13 を表示して SC-01 へ移動する
3. 表示時の値を「変更有無の判定用」として保持する

### 3.2 入力チェック（itemValidator.validate）
画面詳細設計書 SC-05 5章のチェックを、以下の順で行う。すべての項目をチェックし、エラーをまとめて返す（最初のエラーで止めない）。
1. 写真が1枚以上（処理中の写真は数えない）→ MSG-E01
2. 名前が前後の空白を除いて1文字以上 → MSG-E02
3. カテゴリが選択されている → MSG-E03
4. ベースカラーが選択されている → MSG-E04
5. 購入金額が入力されている場合、0〜9,999,999 の整数 → MSG-E05
6. 購入日が入力されている場合、今日以前 → MSG-E06

### 3.3 保存用の値への変換（itemValidator.toItemInput）
1. テキスト項目の前後の空白（全角・半角）を取り除き、空になった項目は null にする
2. 購入金額を数値に変換する（未入力は null）
3. 季節を春→夏→秋→冬の順に並べ、季節コード（DB設計書 共通 5.3）に変換する
4. サブカテゴリが「未選択」の場合は null にする

### 3.4 保存
1. 処理中状態にし、保存ボタンを押せない状態にする
2. `itemValidator.validate` を行う。エラーがあれば各項目に表示し、MSG-E07 をトーストで表示して、最初のエラー項目までスクロールする。処理中状態を解除して終了する
3. `itemValidator.toItemInput` で保存用の値に変換する
4. 登録時：`itemRepository.create` を呼ぶ。トランザクション内で以下を行う
   1. 写真ごとに写真IDを採番し、photos と thumbnails に追加する
   2. 写真IDを写真の並び順に並べて photoIds とする
   3. アイテムIDを採番し、createdAt・updatedAt に現在日時を設定して items に追加する
5. 更新時：`itemRepository.update` を呼ぶ。トランザクション内で以下を行う
   1. 新しく追加された写真に写真IDを採番し、photos と thumbnails に追加する
   2. 表示時の photoIds にあって保存時の並びにない写真を、photos と thumbnails から削除する
   3. items の各項目と photoIds を更新し、updatedAt に現在日時を設定する（createdAt は変更しない）
6. 成功した場合
   - 登録時：SC-01 へ戻り、一覧を先頭までスクロールし、MSG-I01 を表示する
   - 更新時：SC-04 へ戻り、MSG-I02 を表示する（写真は1枚目を表示）
7. 失敗した場合：MSG-E11 をダイアログで表示し、入力内容を保持したまま SC-05 に留まる（トランザクションにより、DBは保存前の状態のまま）

### 3.5 変更有無の判定（キャンセル時）
1. 現在のフォームの値と、表示時に保持した値を比べる（写真は写真の並び、季節は春→冬の順に並べてから比べる）
2. 違いがなければ呼び出し元へ戻る。違いがあれば DL-03 を表示する

## 4. 例外処理

| 状況 | 対応 |
|------|------|
| 編集対象のアイテムが存在しない（3.1） | MSG-E13 を表示して SC-01 へ移動する |
| 書き込みに失敗（容量不足を含む） | MSG-E11 を表示し、SC-05 に留まる（ERROR ログ） |
| 写真の処理中に「保存」が押された | 保存ボタンを押せない状態にしているため発生しない |
