## 1. 概要
カメラで撮影した写真、またはフォトライブラリから選んだ写真を、保存用の画像（長辺1280px）と一覧用画像（400pxの正方形）に変換し、登録・編集フォームに追加する。DBへの書き込みは行わず、保存（P-05）まではメモリ上に保持する。

| 項目 | 内容 |
|------|------|
| 契機 | DL-01 で「写真を撮る」「フォトライブラリから選択」を選び、写真が選ばれたとき |
| 関連画面 | SC-05（DL-01） |
| 関連テーブル | なし（P-05 で書き込む） |

## 2. 関数

| 関数名 | 概要 | 入力 | 出力 |
|--------|------|------|------|
| imageProcessor.process | 写真1枚を変換する | File | NewPhoto（画像Blob、一覧用画像Blob、幅、高さ、各サイズ） |
| useItemForm.addPhotos | 選ばれた写真を順に変換し、フォームの写真の末尾に追加する | File[] | なし |

## 3. 処理フロー

### 3.1 写真の選択
1. 「写真を撮る」：撮影用の入力欄（カメラを起動する設定）を開く。撮影された1枚を受け取る
2. 「フォトライブラリから選択」：複数選択できる入力欄を開く。選ばれた写真を選択順に受け取る
3. 選択画面でキャンセルされた場合は何もしない

### 3.2 フォームへの追加（useItemForm.addPhotos）
1. 追加できる残り枚数（10枚 − 現在の枚数）を求める。受け取った枚数が残り枚数を超える場合は、先頭から残り枚数分だけを対象とし、処理後に MSG-E09 を表示する
2. 対象の写真ごとに、フォームの末尾に「処理中」の写真を追加する（サムネイル位置に処理中表示）。処理中は保存ボタンを押せない状態にする
3. 1枚ずつ順に `imageProcessor.process` を行う（メモリ使用量を抑えるため、並行して処理しない）
4. 成功した写真は「処理中」を完成した写真に置き換える。失敗した写真はフォームから取り除き、MSG-E10 を表示する
5. すべて終わったら、保存ボタンを押せる状態に戻す

### 3.3 画像の変換（imageProcessor.process）
1. 画像ファイルを読み込む。写真の向き情報（撮影時の縦横）を反映して読み込む
2. 長辺が1280pxを超える場合は、縦横比を保って長辺1280pxに縮小する（超えない場合はそのままの大きさ）
3. JPEG（画質0.8）に変換して「画像」とする
4. 元の画像の中央を正方形に切り抜き、400px × 400px に縮小して JPEG（画質0.8）に変換し「一覧用画像」とする
5. 幅・高さ・各サイズ（バイト）を添えて返す。読み込みや変換に失敗した場合は ImageLoadError とする

- iPhoneの写真（HEIC形式）は、選択時にiOSがJPEGに変換して渡すため、アプリ側でHEICを扱う処理は設けない

## 4. 例外処理

| 状況 | 対応 |
|------|------|
| 画像を読み込めない・変換できない | その写真だけ追加せず、MSG-E10 を表示する（WARN ログ）。他の写真の処理は続ける |
| 上限枚数を超えて選ばれた | 先頭から上限まで追加し、MSG-E09 を表示する |
| 処理中にフォームを閉じた（キャンセル） | 処理中の写真は破棄する |

## 5. 確認事項

2026-11-07 のレビューにて、以下の全件について合意済み。

| No | 内容 | 該当箇所 |
|----|------|---------|
| 1 | 複数枚の写真は1枚ずつ順に処理する（同時に処理しない）。処理中の写真はサムネイル位置に処理中表示を出す | 3.2 |
| 2 | JPEGの画質は 0.8 とする（保存用・一覧用とも） | 3.3 |
| 3 | 長辺が1280px以下の写真は拡大せず、そのままの大きさで保存する | 3.3 手順2 |
