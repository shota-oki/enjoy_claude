## 1. 本書の位置づけ
機能設計書で定義したクラス／関数が「どの順序で」「どのような分岐・例外処理を伴って」実行されるかを定義する。画面側からどの処理が呼ばれるかは画面詳細設計書を参照。

## 3. 処理フロー詳細

### 3.1 F-001: ユーザー登録・ログイン

**会員登録（API-001）**
1. クライアントがPOST /api/auth/registerを呼び出す
2. AuthServiceがメールアドレスの重複を確認する（重複していれば409 EMAIL_ALREADY_EXISTS）
3. パスワードの形式を検証する（8文字未満、または英数字混在でなければ400 VALIDATION_ERROR）
4. パスワードをbcryptでハッシュ化しUserを保存する
5. 201でユーザー情報（id, email）を返す

**ログイン（API-002）**
1. クライアントがPOST /api/auth/loginを呼び出す
2. AuthServiceがメールアドレスに一致するユーザーを検索する
3. パスワードハッシュを照合する（ユーザーが存在しない、または不一致の場合は401 INVALID_CREDENTIALS）
4. JwtTokenProviderがアクセストークンを発行する
5. 200でアクセストークンとユーザー情報を返す

### 3.2 F-002: 書誌情報検索・取得（API-003）
1. クライアントがGET /api/books/search?q=＜入力値＞を呼び出す
2. BookSearchServiceが入力値の形式を判定する（数字10桁または13桁ならISBN、それ以外はタイトルとして扱う）
3. OpenBdClientがopenBD APIへHTTPリクエストを送信する
4. openBDからのレスポンスをBookSummary（isbn, title, author, publisher, coverImageUrl）に変換する
5. 該当件数が0件の場合は404 NO_SEARCH_RESULTSを返す
6. openBD API呼び出しがタイムアウトまたはエラーの場合は502 EXTERNAL_API_ERRORを返す

### 3.3 F-003／F-006: 蔵書記録の新規作成（API-005）
1. クライアントがPOST /api/recordsを呼び出す（Authorizationヘッダーにトークン必須）
2. JwtTokenProviderがトークンを検証し、ユーザーIDを解決する（検証失敗時は401 UNAUTHORIZED）
3. RecordServiceが入力値を検証する（statusが「読了」の場合はfinishedDate必須・未来日不可、reviewは1000文字以内、ratingは1〜5）
4. 検証エラーがあれば400 VALIDATION_ERROR（ERR-008／ERR-009に対応）を返す
5. GenreService#findOrCreateでジャンル名からGenreエンティティを解決する（存在しないジャンル名は新規作成）
6. BookRecordRepositoryで蔵書記録を保存し、book_record_genresの関連を保存する
7. 作成した蔵書記録を201で返す

### 3.4 F-004／F-008: 蔵書記録の一覧表示・検索絞り込み（API-004）
1. クライアントがGET /api/recordsを呼び出す（keyword, genre, status, page, sizeを指定可）
2. RecordServiceがトークンからユーザーIDを解決する
3. 検索条件をもとにBookRecordRepository#searchで動的クエリ（JPA Specification）を実行する
4. ページング情報（page, size, totalCount）とともに一覧を200で返す
5. 該当件数が0件の場合も200で空配列を返す（画面側で空状態を表示、画面設計書ERR-011に対応）

### 3.5 F-005: 蔵書記録の編集・削除（API-006, API-007, API-008）

**詳細取得（API-006）**
1. クライアントがGET /api/records/{id}を呼び出す
2. RecordServiceが対象レコードを取得し、user_idがトークンのユーザーと一致するか確認する
3. 一致しない、または対象が存在しない場合は404 RECORD_NOT_FOUNDを返す（所有者以外に存在有無を知らせないため、権限エラーも404として扱う）
4. 一致すれば200で詳細を返す

**更新（API-007）**
1. クライアントがPUT /api/records/{id}を呼び出す
2. 詳細取得と同様に所有者確認を行う（不一致・存在しない場合は404）
3. 3.3と同様の入力値検証を行う（不正なら400 VALIDATION_ERROR）
4. ジャンルの関連を更新後の内容で張り替える
5. 更新後の内容を200で返す

**削除（API-008）**
1. クライアントがDELETE /api/records/{id}を呼び出す
2. 所有者確認を行う（不一致・存在しない場合は404）
3. book_record_genresの関連レコードを先に削除した上でbook_recordsを削除する
4. 削除に失敗した場合は500 DELETE_FAILED（画面設計書ERR-010に対応）を返す
5. 成功時は204（レスポンスボディなし）を返す

### 3.6 F-007: 読書統計表示（API-009）
1. クライアントがGET /api/statsを呼び出す（year指定可、省略時は当年）
2. StatsServiceがトークンからユーザーIDを解決する
3. 指定年のbook_recordsのうちstatus=読了のレコードを抽出し件数を集計する
4. book_record_genres経由でジャンル別件数を集計する
5. 200で集計結果（year, totalCount, genreBreakdown）を返す

## 4. 例外処理方針

- コントローラ層は個別にtry-catchを行わず、共通例外ハンドラ（`@RestControllerAdvice`）で例外からHTTPレスポンスへの変換を一元化する
- 入力値検証エラーはBean Validation（`@Valid`）の`MethodArgumentNotValidException`を捕捉し、400 VALIDATION_ERRORとして返す
- 業務例外（`EmailAlreadyExistsException`、`RecordNotFoundException`等）はカスタム例外クラスとして定義し、例外クラスとHTTPステータス／エラーコードを1対1で対応付ける
- openBD APIとの通信エラー（タイムアウト、5xx応答等）は`ExternalApiException`に変換し、502 EXTERNAL_API_ERRORとして返す。リトライは行わない
- 上記以外の想定外の例外はすべて500 INTERNAL_ERRORとして返し、詳細はログに出力する（レスポンスにスタックトレース等の内部情報は含めない）

## 5. ログ出力方針

| ログレベル | 出力対象 |
|-----------|---------|
| ERROR | 想定外の例外（500 INTERNAL_ERROR）、openBD API呼び出し失敗、DB更新・削除処理の失敗 |
| WARN | 業務例外（400／401／404等、クライアント起因のエラー）、openBD APIのレスポンス遅延 |
| INFO | ユーザー登録・ログインの成功、蔵書記録の作成・更新・削除の成功、アプリケーション起動・停止 |

アプリケーションログは基本設計書の非機能設計方針に基づき3ヶ月保持する。
