## 1. 概要

### 1.1 背景
個人開発の題材として、読んだ本を記録し、あとから振り返られる「読書記録・本棚管理アプリ」の需要がある。既存の読書管理サービスは多機能・多人数向けのものが多く、自分専用にシンプルに読書履歴を残す用途に特化したツールが少ない。また、書誌情報の手入力は手間がかかるため、ISBN等をもとに自動取得できると利便性が高い。

### 1.2 目的
読んだ本の書誌情報（書名・著者・表紙画像等）をISBN検索等で自動取得し、読書ステータス・読了日・感想・評価とともに記録することで、あとから本棚形式・統計で読書履歴を振り返られるWebアプリケーションを提供する。

## 2. 対象範囲（スコープ）

### 2.1 対象とする範囲
- ISBN・タイトル検索による書誌情報（書名・著者・出版社・表紙画像等）の自動取得
- 蔵書記録（本の記録）の作成・編集・削除
- 読書ステータス管理（未読／読書中／読了）
- 読了日・感想・評価（5段階評価等）の記録
- ジャンル・タグ付け
- 蔵書記録の一覧表示（本棚形式）
- 読書統計の表示（年間読了冊数、ジャンル内訳等）
- ユーザーアカウントの登録・ログイン

### 2.2 対象外とする範囲
- 電子書籍そのものの閲覧・貸出・購入機能
- 他ユーザーとの記録共有・レビュー投稿・SNS的機能（将来検討事項とし、本フェーズでは対象外）
- ネイティブモバイルアプリ（iOS/Android）の提供（本フェーズはWebアプリのみ）
- カメラによるバーコードスキャン登録（本フェーズはISBN・タイトルのテキスト検索のみ、将来検討）
- 有償の書誌情報APIの利用（無償枠を超えるサービスは対象外）

## 3. 用語定義

| 用語 | 説明 |
|------|------|
| 蔵書記録 | ユーザーが登録する、書誌情報・読書ステータス・感想・評価を含む1件の本の記録データ |
| 書誌情報 | 書名・著者・出版社・表紙画像など、本そのものの基本情報 |
| 読書ステータス | 未読／読書中／読了など、本の読書進捗を表す状態 |

## 4. 業務要件

| ID | 業務要件 | 説明 |
|----|---------|------|
| BR-001 | 読んだ本の記録 | ユーザーは読んだ本を書誌情報とともに記録できること |
| BR-002 | 読書履歴の振り返り | ユーザーは過去の読書記録を一覧や統計で振り返られること |

## 5. 機能要件

| ID | 機能名 | 概要 | 優先度 |
|----|--------|------|--------|
| FR-001 | ユーザー登録・ログイン | メールアドレス等でアカウントを作成し、ログインできる | 高 |
| FR-002 | 書誌情報検索・取得 | ISBNまたはタイトルで検索し、外部APIから書誌情報を自動取得する | 高 |
| FR-003 | 蔵書記録の新規作成 | 取得した書誌情報に、読書ステータス・読了日・感想・評価を付与して記録する | 高 |
| FR-004 | 蔵書記録の一覧表示（本棚） | 登録した本を本棚形式・一覧形式で表示する | 高 |
| FR-005 | 蔵書記録の編集・削除 | 作成済みの蔵書記録を編集・削除できる | 中 |
| FR-006 | ジャンル・タグ付け | 蔵書記録にジャンルやタグを設定できる | 中 |
| FR-007 | 読書統計表示 | 年間読了冊数やジャンル内訳等の統計を表示する | 中 |
| FR-008 | 蔵書記録の検索・絞り込み | タイトル・著者・ジャンル・ステータスで蔵書記録を検索・絞り込みできる | 低 |

## 6. 非機能要件

| 分類 | 要件 |
|------|------|
| 性能 | ＜要確認：レスポンスタイム等の目標値＞ |
| セキュリティ | ＜要確認：認証方式、パスワード保管方針、読書記録等個人データの取り扱い方針＞ |
| 可用性 | ＜要確認：稼働率目標＞（個人開発のため常時稼働は必須としない想定） |
| 保守性 | ＜要確認：ログ保持期間、バックアップ方針＞ |

## 7. 制約事項
- 個人開発であり、開発・運用リソースが限定される
- 書誌情報の取得には無償で利用できる書誌情報API（例: 国立国会図書館サーチAPI、openBD等）の利用を想定する（＜要確認：採用するサービス・利用規約上の制約（アクセス頻度制限等）＞）

## 8. 前提条件
- 登録する本には基本的にISBNが付与されていること（ISBNのない古書・同人誌等は対象外、またはタイトル手入力での代替登録とする）
