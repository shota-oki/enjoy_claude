## 1. 概要

### 1.1 背景
個人開発の題材として、訪れたご飯屋さん（飲食店）を記録し、あとから振り返られる「グルメ記録アプリ」の需要がある。既存のグルメ系サービスは店舗検索・口コミ投稿が中心で、自分自身の訪問履歴や感想を地図と紐づけて手軽に振り返る用途に特化したサービスが少ない。

### 1.2 目的
訪れたご飯屋さんの位置・写真・メモ・評価を地図上に記録し、あとから時系列や地図で振り返られるWebアプリケーションを提供する。将来的には不特定多数のユーザーへの公開も見据える。

## 2. 対象範囲（スコープ）

### 2.1 対象とする範囲
- ご飯屋さん（飲食店）単位での訪問記録（位置情報付き）の作成・編集・削除
- 地図上への訪問記録の表示（ピン表示）
- 無償で利用できる地図サービス（OpenStreetMap等）との連携
- 訪問記録への写真添付
- 訪問記録への本文メモ・評価（例: 5段階評価、また行きたいフラグ）の入力
- ジャンル（和食・ラーメン・カフェ等）によるタグ付け
- 訪問記録の一覧表示（時系列順）
- ユーザーアカウントの登録・ログイン

### 2.2 対象外とする範囲
- 飲食店以外の場所（観光地・自宅等）の記録機能（本フェーズは飲食店に特化）
- ネイティブモバイルアプリ（iOS/Android）の提供（本フェーズはWebアプリのみ）
- 他ユーザーとの記録共有・口コミ投稿・SNS的機能（将来検討事項とし、本フェーズでは対象外）
- オフライン利用（PWA化含む）
- 有償の地図・検索APIの利用（無償枠を超えるサービスは対象外）

## 3. 用語定義

| 用語 | 説明 |
|------|------|
| 訪問記録 | ユーザーが登録する、ご飯屋さんの位置情報・写真・メモ・評価を含む1件の記録データ |
| ピン | 地図上に表示される訪問記録の位置マーカー |
| ジャンル | ラーメン・カフェ・和食など、飲食店の種別を表すタグ |

## 4. 業務要件

| ID | 業務要件 | 説明 |
|----|---------|------|
| BR-001 | ご飯屋さんの記録 | ユーザーは訪れたご飯屋さんを位置情報付きで記録できること |
| BR-002 | 記録の振り返り | ユーザーは過去に訪れたご飯屋さんを地図または時系列で振り返られること |

## 5. 機能要件

| ID | 機能名 | 概要 | 優先度 |
|----|--------|------|--------|
| FR-001 | ユーザー登録・ログイン | メールアドレス等でアカウントを作成し、ログインできる | 高 |
| FR-002 | 訪問記録の新規作成 | 現在地または任意の店舗の位置を指定し、メモ・写真・評価とともに記録を作成する | 高 |
| FR-003 | 訪問記録の地図表示 | 作成した訪問記録を無償の地図サービス上にピンとして表示する | 高 |
| FR-004 | 訪問記録の一覧・時系列表示 | 訪問記録を日時順のリストで表示する | 高 |
| FR-005 | 訪問記録の編集・削除 | 作成済みの訪問記録を編集・削除できる | 中 |
| FR-006 | 写真添付 | 訪問記録に1枚以上の写真を添付できる | 中 |
| FR-007 | ジャンルタグ付け | 訪問記録にジャンル（ラーメン・カフェ等）を設定できる | 中 |
| FR-008 | 訪問記録の検索・絞り込み | 日付・ジャンル・キーワードで訪問記録を検索・絞り込みできる | 低 |

## 6. 非機能要件

| 分類 | 要件 |
|------|------|
| 性能 | 主要画面（一覧・地図表示）のレスポンスタイム3秒以内 |
| セキュリティ | メールアドレス＋パスワードによる認証。パスワードはbcrypt等でハッシュ化して保存。全通信をHTTPS化。位置情報・写真等の個人データは本人（および将来共有機能を実装する場合は許可したユーザー）のみ閲覧可能とする |
| 可用性 | 個人開発のためSLAは定めず、ベストエフォート運用（目安として稼働率95%程度）。障害時は可能な範囲で速やかに復旧する |
| 保守性 | アプリケーションログは3ヶ月保持。データベースは週次でバックアップを取得する |

## 7. 制約事項
- 個人開発であり、開発・運用リソースが限定される
- 地図表示・位置検索は無償で利用できる地図サービスに限定する。OpenStreetMap＋Leaflet.js（地図表示、APIキー登録不要）、および店舗名からの住所検索が必要な場合はOSM提供のNominatim（無償のジオコーディングAPI）の採用を推奨する（利用規約上、アクセス頻度・タイル配信ポリシーの制限に注意）
- 将来的な一般公開を見据えるため、個人情報・位置情報の取り扱いについてプライバシーポリシーの整備が必要となる可能性がある

## 8. 前提条件
- 利用者はスマートフォンまたはPCのブラウザから位置情報の取得を許可すること
- 開発初期は不特定多数への公開前提の設計としつつ、実際の公開時期・範囲は別途判断する
