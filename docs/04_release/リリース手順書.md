## 1. 概要
アプリを GitHub Pages に公開する手順を定める（方式設計書 M-03）。公開は、main のコミットに版のタグ（`v1.0.0` など）を付けて push すると GitHub Actions（`.github/workflows/deploy.yml`）が自動で行う。

- 公開URL：`https://shota-oki.github.io/enjoy_claude/`
- 版数の付け方：M-03 3章（最初の公開は 1.0.0）

## 2. 初回のみ行う設定（GitHub の画面）

| No | 設定箇所 | 内容 |
|----|---------|------|
| 1 | Settings → General → Danger Zone | リポジトリを公開（Public）にする（無料プランの GitHub Pages の条件。M-03 2章） |
| 2 | Settings → Pages → Build and deployment | Source を「GitHub Actions」にする |
| 3 | Settings → Environments → github-pages → Deployment branches and tags | 「Add deployment branch or tag rule」で、種類を Tag、パターンを `v*` として追加する（初期設定では main ブランチからしか公開できず、タグからの公開が拒否されるため） |

## 3. リリース前チェックリスト
- [ ] 公開する変更が main に取り込まれ、main の「検査」（`.github/workflows/ci.yml`）が成功している
- [ ] システムテスト（iPhone 実機）が完了している（`docs/03_test/`）
- [ ] DB構造を変えた版の場合、旧版のデータを入れた状態からの更新をテストした（M-01 5章）
- [ ] `app/` で `npm audit --omit=dev` を実行し、本番で使うパッケージに脆弱性がない（公開処理でも確認し、あれば公開を中止する）
- [ ] 開発用パッケージの脆弱性（`npm audit`）を確認し、対応要否を判断した

## 4. リリース手順

| 手順No | 作業内容 |
|-------|---------|
| 1 | 作業ブランチで `app/` に移動し、`npm version 1.0.0 --no-git-tag-version` で `package.json`・`package-lock.json` の版数を上げてコミットする（版数は M-03 3章に従う） |
| 2 | 作業ブランチを main に取り込み、main を push する |
| 3 | main の最新コミットに版のタグを付けて push する：`git switch main` → `git pull` → `git tag v1.0.0` → `git push origin v1.0.0` |
| 4 | GitHub の Actions 画面で「公開」が成功したことを確認する。失敗した場合は公開されず、それまでの版が公開されたまま残る（失敗理由を確認し、修正後に新しい版数で手順1からやり直す） |

公開処理（`deploy.yml`）が行うこと：
1. タグと `package.json` の版数が一致すること、タグのコミットが main に含まれることを確認する
2. 本番で使うパッケージの脆弱性を確認する（`npm audit --omit=dev`）
3. 検査（lint・型チェック・テスト）を実行する
4. 公開URLに合わせたパス（`BASE_PATH=/enjoy_claude/`）でビルドし、GitHub Pages に配置する

## 5. リリース後の確認（M-03 5章）
- [ ] iPhone のホーム画面のアプリを開き、「新しいバージョンがあります」の案内が出ること（案内は起動時、または前回の確認から1時間以上経って前面に戻ったときに出る）
- [ ] 「更新」を押すと再読み込みされ、SC-01 が表示されること
- [ ] SC-06 の「バージョン」が新しい版数になっていること
- [ ] 既存のデータ（アイテム・写真・サブカテゴリ）が表示されること

## 6. 切り戻し手順
1. GitHub の Actions 画面で「公開」を選び、「Run workflow」を押す
2. 「Use workflow from」で、戻したい版のタグ（例：`v1.0.0`）を選んで実行する
3. iPhone で 5章の確認を行う（案内が出て、更新後に戻した版数が表示される）

- DB構造を変えた版のあとは前の版に戻せない。その場合は修正版を新しい版数で公開する（M-01 5章）

## 7. 確認用データ（性能テスト）
300件・写真付きの確認用データは、PC の `app/` で `npm run seed:sample` を実行し、表示された `https://<PCのIPアドレス>:5173/` を iPhone の Safari で開くと作成される（テスト方針書）。

- アイテムが1件もない場合だけ作成する。作成中は進み具合が表示され、終わると SC-01 が表示される
- 公開URLとは別のアドレスのため、公開版のデータには影響しない
- 作り直す場合は、iPhone の「設定 → アプリ → Safari → 詳細 → Webサイトデータ」でPCのIPアドレスのデータを削除してから開き直す

## 8. 確認事項

| No | 内容 | 該当箇所 |
|----|------|---------|
| 1 | 公開処理で本番用パッケージの脆弱性（`npm audit --omit=dev`）があれば公開を中止する。開発用パッケージの脆弱性は公開を止めず、リリース前に確認する | 3章、4章 |
| 2 | 検査（`ci.yml`）では lint・型チェック・テストに加え、ビルドも行う（M-03 4.1 に追加） | 4章 |
| 3 | 切り戻しは、公開処理を手動実行して戻したい版のタグを選ぶ方法とする | 6章 |
