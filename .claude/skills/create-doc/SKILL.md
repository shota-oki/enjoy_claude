# create-doc

`docs/` 配下に用意されている成果物テンプレートをもとに、実際のドキュメントを作成・更新するスキルです。

## 手順

1. **対象の特定**
   - 引数または会話内容から、作成したい成果物名（例:「要件定義書」「基本設計書」「DB設計書」「単体テスト仕様書」など）を特定する。
   - 曖昧な場合やフェーズ名のみ指定された場合（例:「設計書」）は、`docs/README.md` の対応表を提示してユーザーに絞り込みを確認する。

2. **テンプレートの特定と読み込み**
   - `docs/README.md` の対応表から、対象成果物の格納ディレクトリを特定する。
   - 対応するテンプレートファイル `docs/<格納先>/<成果物名>_template.md` を読み込む。

3. **関連ドキュメントの確認**
   - テンプレート内の「関連文書」や項目の性質から、参照すべき前工程の成果物（例: 基本設計書作成時は `docs/01_requirements/要件定義書.md`）が存在するか確認し、存在すれば読み込んで整合性を取る。
   - 前工程の成果物が未作成の場合は、その旨をユーザーに伝えた上で作成を続けるか確認する。

4. **内容の作成**
   - 会話でこれまでに得られている情報、および関連ドキュメントの内容をもとに、テンプレートの各項目（＜　＞で示されたプレースホルダー）を埋める。
   - ユーザーへのヒアリングが必要な項目（例: 非機能要件の具体的な数値、承認者名など）は、埋められる範囲を埋めた上で、不明点をまとめてユーザーに質問する。
   - 憶測で数値や仕様を作り上げない。不明な項目はプレースホルダーのまま残すか、「要確認」と明記する。

5. **保存**
   - 保存先は同じディレクトリ、ファイル名はテンプレートから `_template` を除いたもの（例: `要件定義書_template.md` → `要件定義書.md`）。
   - 同名ファイルが既に存在する場合は、上書き・追記・別バージョンとして保存のいずれを希望するかユーザーに確認してから進める。

6. **完了報告**
   - 作成したファイルパスを提示する。
   - プレースホルダーのまま残った項目や、ユーザー確認が必要な項目があれば一覧にして提示する。
